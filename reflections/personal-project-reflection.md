# Personal Project: Final Reflection

I ultimately found this project to be very rewarding and valuable in working towards my two semester goals: building effective AI usage skills, and producing original designs. 

Throughout the process of researching my problem and bad situation, I found it very important to rely on my own prior knowledge of the domain (Minesweeper community) and develop understanding of what players needed without relying on AI to implement a solution. I believe this gave me a strong basis for understanding the core issues to be addressed by the app, and I would later be able to easily judge whether a certain implementation supported the experience I wanted to create. When moving onto concept design, I still found it important to withhold relying on AI, and I only used it once I had a complete draft of my concepts ready; from there, I used ChatGPT to give me wording suggestions, and check for any edge cases I might have missed. I prioritized that I fully own my design in this stage, so that I wouldn’t be confused about how to make design modifications later down the line. My independent inquiry ultimately made these steps feel very creative and innovative, as I had hoped from the start.

The implementation phase was where I started to build generative AI usage skills. I established an iterative workflow where I would first prompt my AI tool to implement something according to my design (either described in the prompt, or documented in markdown), then review all code modifications myself, and finally return another prompt with a numbered list of fixes I wanted to make (and I would repeat this until I was happy with all new changes). I made sure that there were no sections of code that I didn’t understand myself; I could ask the AI to explain its implementation to me, but in implementation cases like the pseudorandom highlight color assignment, I typically gave AI explicit steps for how to simplify the logic. I was also surprised how creative the implementation process was, since I initially overlooked various specific design details like session lifecycle; I enjoyed brainstorming my own revisions to my existing concepts, and seeing my app slowly improve.

There was one major hiccup in my workflow, which was my late realization of high latency for large boards. I was initially quite frustrated to discover this, since I had already written four of my five concepts, and fixing this required end-to-end changes to incorporate per-cell board updates. This moment made me reflect on my testing strategy, since I had mainly been testing on small boards, which didn’t expose this issue until relatively late in the design process. I ultimately found this redesign manageable having fully understood my initial design and testbench, but in the future, I would be more careful to test parameter edge cases earlier so as to avoid a late redesign.

User testing was also very insightful, as during my implementation process, I found it hard to preempt what users might find confusing given I wrote the workflows myself. For instance, I didn’t expect my “Configure and Start Game” task to cause issues, though it exposed a clear recoverability flaw that Jason experienced. Seeing other users interact with the page gave me new insights into potential improvements, but also helped improve my confidence in the usability of the app; for example, I was happy to see both my participants wanted to continue playing after the test was over :). Debriefing also offered new feature ideas, such as a suggestion from Max to add click animations like minesweeper.online’s game playback feature. The testing process made my app feel much more alive, and reminded me of how important it is to stay collaborative and user-oriented when building software.
